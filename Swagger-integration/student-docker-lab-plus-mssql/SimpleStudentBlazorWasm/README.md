# SimpleStudentBlazorWasm

The Students frontend built with **Blazor WebAssembly** (.NET 8, standalone). The whole app — C# code
included — is **downloaded into the browser and runs there**. It uses the same components and the same
typed client (generated from `swagger.json`) as `SimpleStudentBlazorServer`, and works with the
**.NET, PHP and Python APIs**. Lietuviškai: [README_LT.md](README_LT.md).

## How it works

```
                 1. downloads index.html, app .dll files and the .NET runtime (.wasm)
Browser ◄──────────────────────────────────────────── nginx container (static files only, no .NET)

Browser ──HTTP + JSON (fetch)──► API (.NET :6001 / PHP :6002 / Python :6003)
   ▲  2. the C# code runs HERE and calls the API directly – the API must allow it with CORS
```

- After the first download the server is not needed any more: clicks, validation and page changes are
  handled in the browser. Only the API is called.
- The **browser** sends the API requests, so the API addresses must be reachable **from the browser**
  (`http://localhost:6001`, not the Docker name `simplestudentapi:8080`) and the API must send
  **CORS** headers (`Access-Control-Allow-Origin`). All three APIs do:
  .NET — `AddCors()` / `UseCors()` in `SimpleStudentApi/Program.cs`, PHP — `Http::cors()`,
  Python — `CORSMiddleware` in `main.py`.
- Open the browser's developer tools (F12 → **Network**): you see every request to the API —
  with Blazor Server or Razor Pages you would see none, because the server calls the API.

## Compared with SimpleStudentBlazorServer

The pages (`Pages/`, `Layout/`, `Shared/`) are the **same components**. What differs:

| | Blazor Server | Blazor WebAssembly |
|---|---|---|
| Project SDK | `Microsoft.NET.Sdk.Web` | `Microsoft.NET.Sdk.BlazorWebAssembly` + 2 NuGet packages |
| `Program.cs` | `WebApplication` + `AddInteractiveServerComponents()` | `WebAssemblyHostBuilder` (runs in the browser) |
| HTML shell | `Components/App.razor` | `wwwroot/index.html` |
| Settings | `appsettings.json` (secret values possible) | `wwwroot/appsettings.json` — **public**, every visitor can download it |
| HttpClient | from `IHttpClientFactory` on the server | `new HttpClient()` = the browser's `fetch()` |
| Hosting | ASP.NET Core server (.NET runtime) | any static web server (here nginx) |

```
SimpleStudentBlazorWasm/
├── Program.cs                  ← WebAssemblyHostBuilder, reads "Backends" from wwwroot/appsettings.json
├── App.razor                   ← router
├── Layout/  Pages/  Shared/    ← the same components as in SimpleStudentBlazorServer
├── Services/ApiConnection.cs   ← selected backend + typed client (HttpClient → browser fetch)
├── ApiClient/                  ← StudentApiClient.g.cs generated by NSwag + generate-client.sh/.ps1
├── wwwroot/
│   ├── index.html              ← page that loads blazor.webassembly.js
│   ├── appsettings.json        ← API addresses AS SEEN BY THE BROWSER
│   └── app.css
├── nginx.conf                  ← serves the static files; unknown paths → index.html
└── Dockerfile                  ← build with the .NET SDK, run with nginx
```

## Run with Docker

From the folder `student-docker-lab-plus-mssql`:

```bash
docker-compose -f docker-compose.infra.yml up -d
docker-compose up --build
```

Open **http://localhost:6041**. The first load takes a few seconds (the .NET runtime is downloaded),
later loads come from the browser cache.

## Run locally (dotnet run)

The APIs must be running; the addresses are in `wwwroot/appsettings.json`.

```bash
dotnet run
```

Open **http://localhost:6041**. A PHP API in XAMPP runs at another address — change its `Url` in
`wwwroot/appsettings.json`, e.g. `http://localhost/simpleStudentApi`.

## Troubleshooting

| Problem | Fix |
|---|---|
| "Cannot reach the API: TypeError: Failed to fetch" | the API is not running **or** it does not allow CORS – check F12 → Console: a CORS error says which header is missing |
| CORS error only for the .NET API | the API image is old – rebuild it: `docker-compose up --build simplestudentapi` |
| API address with `simplestudentapi:8080` does not work | that name exists only inside Docker; the browser needs `localhost:6001` |
| Blank page, "Loading the .NET runtime…" stays | F12 → Console; usually a failed download of `_framework/*` files – rebuild the image |
| Changed `wwwroot/appsettings.json` has no effect | the browser cached it – reload with Ctrl+F5 (Cmd+Shift+R) |
